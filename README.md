# 云州江湖志

一个基于 Next.js 16、Node 内置 SQLite 和 WebSocket 的多人文字武侠游戏 demo。首次访问会自动生成并持久化独立角色；不同浏览器共享八方向网格地图、在线位置、世界动态和聊天消息。

初始地图从“嬴长嫚与楼夜秋之家 - 玄关”开始，现代住宅保持不变，屋外的楼门路向西通往北宋东京开封府，向东止于“东境建设中”。帕洛斯地图已经完全移除。内置种子包含一张连续大世界、住宅、五座开封公共建筑和八家代表性宋式店铺的单层平面，共16个区域、1,050个可达地点和1,100条路线；所有地点都能从玄关抵达。开封公共地图仍有935个地点，其中约120个原有街路格现在是具名店铺门面；大内宫城、开封府署、大相国寺、国子监、潘楼酒店和八家店铺均从大地图入口进入，不继续嵌套楼层。

## 本地运行

推荐使用 Node.js 24 LTS。

```bash
npm install
npm run dev
```

访问 <http://localhost:3000>。如果需要模拟多名玩家，可使用不同浏览器或普通窗口与隐私窗口分别访问。

地图中的地点使用紧凑长方形框显示，默认加载当前地图内从当前位置出发三步可达的地点；成功开启鹰眼后，三十分钟内会按技能等级临时扩大到最多八步，但不会把未到达地点写入足迹。局部地图用当前数据生成区域底板和坐标骨架，以硬边阴影形成节点厚度；当前位置与一步道路处于前景，二至三步路网逐层退到中、后景，方向标记则固定说明上下左右。地图仍然没有背景图片，地点框内只显示短名称，完整名称、区域、坐标、轻功信息与可见结构统计放在外部状态栏。粗实线与数字 1 表示普通下一步；额外的青色双线框表示可立即施展轻功抵达，冷却中则改为不可点击的虚线双框。地图下方的“下一步”栏仍会列出明确的上、下、左、右及四个斜向普通移动按钮。“足迹地图”按钮会按需打开该角色亲自到达过的完整地图，可在已到访的大世界、住宅与建筑平面之间切换；未探索地点不会提前显示。同名道路由独立 ID 和网格坐标区分。房门、宫门、楼梯、道路、渡船和传送门等跨图连接只出现在行动栏，不占用八方向槽位。若右上角不是“江湖在线”，移动按钮会暂时禁用，等待 WebSocket 重连后即可继续。

快速旅行只在足迹地图中开放。青绿色虚线地点框表示已经亲自到达并解锁的枢纽；住宅玄关、东京入口、主要城门、州桥和重要建筑入口可成为枢纽。“东境建设中”不是快速旅行点。快速旅行不消耗耐力，但战败、战斗中或正在执行现实时间行动时不能使用；未到访地点、普通地点和客户端伪造的地点 ID 都会被服务器拒绝。

局域网内通过普通 HTTP 和服务器 IP 访问时也可以移动和编辑地图；客户端不依赖仅在安全上下文中提供的 `crypto.randomUUID()`。

常用命令：

```bash
npm test          # 数据库与游戏规则测试
npm run test:e2e  # Playwright 全入口与功能测试
npm run test:all  # 单元测试与 Playwright 测试
npm run lint      # ESLint
npm run build     # Next.js 与自定义服务端生产构建
npm start         # 启动生产服务
npm run db:backup # 在线安全备份 SQLite
npm run map:seed  # 幂等导入完整演示世界并校验
npm run map:validate # 校验来源、层级、方向槽与全图可达性
npm run map:seed-load -- --locations=50000 # 生成五万地点性能数据
```

## 角色、属性与修炼

角色有力量、敏捷、体质、根骨、悟性和精神六项基础属性。气血、派生耐力、最小/最大攻击、防御、速度、命中、闪避、暴击、暴伤和修炼速度都由服务器公式计算。移动和普通行动不检查也不消耗耐力。

角色栏的“技能”页把已学技能分为主动与被动两组。点击技能条目会先打开详情弹窗，显示关联属性、等级、经验、配置持续时间、当前剩余效果和冷却，再确认发动或主动停止。鹰眼等主动技能立即结算、不进入行动队列；成功后效果持续时间与冷却分别持久计时，主动停止只结束效果，不会清除冷却。潜行等尚未绑定规则的技能保持禁用；轻功是无持续时间的瞬时技能，落点仍通过地图双线边框选择。

境界依次为凡人、后天、先天、宗师、大宗师、炼气、筑基、金丹、元婴、化神、炼虚、合体和大乘，每个境界有12级。小等级奖励为 `2 + floor(境界序号 / 2)` 点属性；突破新境界奖励为 `12 + 3 × 新境界序号` 点，因此境界越高获得的属性点越多。属性分配永久保存，demo 不提供洗点。

从门厅经主卧向下走到同一层的修炼房即可开始修炼。在线和离线修为只按服务器时间结算且没有离线时长上限。境界第9至12级的突破成功率分别为45%、60%、75%和100%；失败扣除突破修为，成功保留30%修为并获得新境界属性点。

## 现实时间行动与生活需求

行动面板按当前地点设施列出可做事项，并明确显示现实耗时、服务器检定成功率和结果范围。角色同时只能进行一个前台行动，另外可以安排最多八个后续行动；队列支持调整顺序和取消，离线期间仍按服务器时间继续。普通相邻移动保持即时，但正在睡眠、观察、工作等前台行动时必须先等待完成或取消。

饱食、饮水和卫生会随现实时间降低，疲劳和如厕需求会升高。每项严重不良需求会让属性/技能检定降低5%，合计最多降低25%，但不会直接导致死亡或消耗移动耐力。现有住宅房间已经配置饮水、用餐、如厕、洗漱、沐浴、睡眠、研读、修炼和练体；所有地点均可观察和聆听，东京开封府街巷、城门与桥梁可扎营，街市、瓦子和宋式店铺可做工。

观察会返回当前地点说明和可用设施；聆听至多返回附近三条公开、非成人行动痕迹。两者和鹰眼结果都只保存在角色自己的行动记录中。鹰眼立即发动，效果与冷却默认各30分钟；可以提前停止视野效果，但仍要等原冷却结束。轻功目标不依赖道路，只能选择同一地图层内二至七格的上、下、左、右或四个斜向直线地点；点击特殊地图边框后立即检定并进入60秒冷却，不会占用或加入行动队列。成功时立即移动并记录足迹，失败时留在原地、损失少量气血并增加疲劳，失败同样触发冷却。

## 钱贯与宋式店铺

货币以整数“文”保存并按 `1贯=1000文` 显示。旧存档在数据库 schema v10 首次升级时按 `1银两=1贯=1000文` 一次性迁移；之后旧 `silver` 字段不再参与游戏。新角色与 NPC 的初始钱袋、行动收入、直接交易、战败掉落、拾取和店铺买卖都通过 `player_wallets` 结算，并在 `currency_ledger` 留下金额、余额、原因和关联记录。

开封120个街面店铺均有持久营业数据，八家可进入店铺的六个单层房间也能使用同一家柜台。行动栏会显示“查看店铺”，点击后打开详情弹窗，列出中国标准时间营业时段、钱袋、店柜现钱、货物说明、有限库存、买价与收购价。购买会扣钱、增加店柜和减少库存；出售仅接受该店经营且未绑定、未装备、未被行动预留的物品，并受店柜现钱限制。确认后，钱包、流水、库存、店柜、物品和交易记录在同一个 SQLite 事务中更新；重复的请求编号不会造成二次扣款。重启或重新导入地图不会补满已经消耗的库存。

带有 `market` 设施的街市、店铺和交易空间还会显示“打开市易行会”。行会提供粳米、茶饼、绫罗、食盐、木材、铁料、楮纸、药材、灯油和铜料十种现货标的，以及按中国标准时间 20:00 到期的1日、7日、30日期货和欧式看涨/看跌期权。所有报价都是整数文；订单按价格优先、同价时间优先撮合，允许部分成交和取消，公会每分钟提供有限双边做市单。期货买卖会形成多头或空头，期权买入获得权利、卖出则形成义务；到期只做现金结算。

期货初始/维持保证金为名义价值的20%/10%，卖出期权为25%/15%。服务端始终只保留十种现货与每种标的各一套1/7/30日期货、看涨和看跌，共100个活动合约；某一套到期结算后才生成对应替代合约，不会随日期无限增长。独立60秒服务器时钟会在没有玩家打开市场时照常定价、盯市、到期和清算，打开的市场弹窗收到 `market.updated` 后刷新。未成交现货/权利金/衍生品保证金会跨合约统一预留，店铺和直接交易不能重复花费；取消请求可安全重放。低于维持保证金时服务端自动关闭风险仓位；钱包不足的损失进入带审计流水的清算债务，新单会被拒绝，之后市场收益优先偿债。市场弹窗展示标的、标记价、买一/卖一、到期、乘数、钱袋、保证金、债务、持仓和未成交委托，并要求明确确认价格与数量。

## 玩家交往、同意与交易

“交往交易”页只列出同地点在线角色，可以问候、发送结交/结义/师徒/恋人/婚配请求、发起交易或屏蔽对方。正式关系只有对方接受后才建立，任何一方都能结束；屏蔽会立即撤销双方未处理的互动和交易。

成人内容默认关闭且角色年龄状态为未知。私密成人行动必须同时满足：双方都把角色状态确认为成年、双方都开启成人内容、双方仍在同一地点、邀请方为这一次具体行动发出请求、受邀方在五分钟内明确接受。每次行动都必须重新请求，接受关系或开启总开关不会形成永久同意；未成年或未知年龄角色不能参与。结果只写入双方个人记录，不进入世界动态。

直接交易先由对方接受，再由双方分别用“文”报价。绑定、已装备或被行动预留的物品不能报价；任一方修改报价都会清空双方确认。第二位玩家确认时，服务端会再次校验地点、钱贯和物品，并在一个 SQLite 事务中交换所有内容及写入双方流水，避免只完成一半。

## 回合战斗、掉落与复起

同地点在线角色可以在任何地图地点直接发起战斗，目前没有安全区。战斗由服务器按30秒回合计时，只有当前行动者能选择普通攻击、命中较低但伤害较高的蓄力猛击、让下一次伤害减半的格挡或按双方速度检定逃跑。回合超时会自动格挡；同一角色连续三次错过自己的回合会自动脱离，逃跑和自动脱离都不产生战败掉落。

气血归零才算战败。战败者的全部个人钱贯与所有未绑定个人物品（包括已装备的未绑定装备）会原地形成公开战利品，绑定物品保留；任何仍在该地点且未参战/未落败的角色可以一次拾取整堆。钱贯掉落与拾取均写入流水。真人角色需要点击“返回玄关复起”，以一半气血回到玄关并保留十分钟受伤状态标记；NPC 不能手动复起，会在战败后整十分钟按届时日程回到工作地或住宅并恢复一半气血。店铺库存和柜上现钱属于店铺而非店主个人，店主战败、被拾取或归来都不会改变店铺资产。

## 开封法度

世界状态栏的“开封法度”按钮会打开通缉详情。只有真人在宋/开封辖区针对 NPC 居民的行为记案：发起袭击 +20、击败 +50、拾取该居民掉落 +50；三项使用战斗/掉落 ID 分别幂等记录，所以完整袭击、击败并夺物会累计120。通缉值每经过完整一小时自然减少1点，并保留不足一小时的余量。

通缉值达到20时，店铺仍允许查看货物，但会显示拒绝原因并禁用买卖；达到50时，在线巡检公人会通过私有 NPC 日程指令沿合法道路追缉，同地点才发起普通战斗。通缉值、追缉目标和控制器身份不会显示在地图地点框或公开人物卡中。活着、空闲、未参战的玩家可在“开封府署·府署正堂”打开法度详情，明确确认按 `通缉值 × 100文` 缴罚；钱贯、流水、投案记录与销案在一个事务中完成，请求重放不会重复扣款。

## 持久 NPC 与独立控制进程

数据库启动时会幂等生成240个持久 NPC；它们使用完整的玩家、属性、需求、物品、行动、战斗和位置数据，不是临时地图标记。城市人口固定分为120名店主、24名帮工/手艺人、24名商贸人员、16名巡检公人、16名街巡门军、16名僧士医伎和24名坊民行旅。120家店铺各有一名独立店主，所有居民都有开封职住地、每天六段中国时间日程、可复用城市路线和共72条公开关系。已有 NPC 的物品、位置、技能、行动、好感和委托不会在重启时重置。公共在线角色与地图 presence 不返回控制器类型，因此 NPC 与真人仍使用相同的姓名、称号和位置结构。

地图节点继续只显示地点短名；NPC 不会塞进地图方块。当前地点的人物集中列在地图下方“此地人物”条中，点击任意同地点人物会打开无障碍详情弹窗。居民详情只显示职业、公开传记、工作地、当下行止、与你的好感、公开城中关系、固定话题和委托，不会返回控制器类型、凭证、稳定键、隐藏性格/目标或日程路线指令。问候每天按中国日期最多增加一次好感。

每名居民提供一个访问、行动或交货委托。接受时会固化目标、报酬和期限；“委托”页签根据足迹时间、成功行动日志或当前可交付物品实时显示进度。交货只接受未绑定、未装备、未被行动预留的物品。回到发布人身边复命后，物品扣除、钱贯流水、好感变化与完成记录会在同一个 SQLite 事务中结算；请求重放不会重复发放报酬。

NPC 由第二个常驻进程管理。先启动游戏服务，再启动 runner：

```bash
npm run build
npm start
npm run npc:start
```

runner 默认建立240个隔离 WebSocket actor，每个都用自己的 Bearer 凭证登录 `/ws` 并发送与浏览器相同的移动、行动、战斗和拾取协议。每次决策前 runner 会重新同步权威快照；战败/战斗优先，其次遵守服务端私下计算的中国时间日程。日程移动使用当前活动道路做 BFS，每次只下发一个普通道路或建筑过渡的相邻步，绝不传送；到达后才执行适合剩余时段的地点行动。`npc.directive` 仅发送给对应 Bearer NPC socket，不会进入浏览器快照或公开人物资料。可用 `NPC_COUNT` 限制本地运行数量，用 `NPC_SERVER_URL` 指向游戏 WebSocket；生产环境必须设置相同且保密的 `NPC_RUNNER_SECRET` 给游戏服务和 runner。设置 `NPC_CONTROLLER_URL` 后，runner 会把角色上下文发给外部 HTTP 控制器，并只接受白名单中的游戏指令，为以后接入独立 AI/LLM 控制器保留边界。

NPC 商贸使用完全独立的 `market-trade` 凭证和进程：

```bash
npm run npc:trade:start
npm run npc:trade:replay -- --decision=<决策ID>
```

商贸 socket 不接收游戏快照或日程、不计在线人数，也不能移动、聊天、战斗、编辑或调用玩家社交协议。默认策略由稳定 NPC ID 确定性生成；可设置 `NPC_TRADE_STRATEGY_URL` 获取一次严格校验且最多32KB的策略，超时/无效时自动保留内置策略。每轮会先持久化策略哈希、精简市场输入、输入哈希和复演种子，再由代理计算一个下单、撤单或观望输出；服务端必须用已存数据复演出逐字节一致的输出，先保存输出再按普通市场规则执行。`npc:trade:replay` 只读比较存储与复演哈希，绝不提交订单。

角色的“物品装备”页保存可堆叠材料和独立装备实例，物品具有品质、绑定、耐久、词条和装备槽。点击物品条目会打开详情弹窗，展示完整说明、数量/预留、品质、耐久、绑定、装备位和效果；装备、卸下或使用需在弹窗内确认。新旧角色只会领取一次绑定的基础衣物、布靴、木剑、农具和最低生活物资；已经消耗或售出的初始物资不会因读取行囊再次生成。物品目录另含药材、茶饼、蜜糕、食盐、灯油、绫罗、麻布、楮纸、松烟墨、经义抄本、铜镜和澡豆等宋式商品。

厨房、工坊和锻造设施会显示当前可用配方。开始制作时只预留输入物资，取消行动会完整释放，成功完成才原子扣除并生成成品。前庭、后庭和温室各有持久农田；播种和收获各需现实30分钟，药草与水稻分别按现实30天和120天成长，生长过程不占用角色行动位置。

## 地图设计工具

访问 <http://localhost:3000/map-editor>，或在游戏世界状态栏点击“地图设计”。开发模式默认开放编辑便于本地演示；生产模式仅允许数据库角色为 `editor`/`admin`、列入 `EDITOR_PLAYER_IDS`，或显式启用 `EDITOR_ALLOW_ALL=true` 的角色修改共享地图。

- 地点拖放后自动吸附到最近的空网格。
- 普通路线只允许上、下、左、右、左上、左下、右上、右下八个相邻方向，并且每个方向最多一条。
- 可以新增、改名、调整父级和删除空的地图层；服务端会拒绝父子层循环。
- 普通路线只能连接同层相邻格；跨层目标可按地图层和名称搜索，再选择门、楼梯、电梯、关门、道路、渡船、地下城、快速传送或传送门。
- 大区域或公共区块由两分钟租约锁保护，每30秒续租；完成编辑后主动释放。
- 新增、移动、缩放和连接会自动保存，并支持当前租约内最近50步撤销/重做。
- 地图按9、25或49个空间区块加载；低缩放仅显示区域和区块聚合，详细响应最多返回1200个地点。

## 行动规则设计工具

访问 <http://localhost:3000/action-editor>，或在游戏世界状态栏点击“行动设计”。生产环境的规则读取仍可供游戏使用，但创建、修改、停用与地点绑定只允许授权编辑者执行。

- 可以创建、修改、版本检查和软停用行动模板，分别配置行动耗时、技能效果持续秒数、冷却、分类、目标、可见性和结果文本；技能持续时间会安全写入成功结果，无需手改 JSON。
- 需求、检定、成本、成功结果和失败结果使用经过 Zod 白名单校验的 JSON 对象；不能写入或执行任意 JavaScript/SQL。
- 可以按地图和名称查找地点，把 self/location 行动绑定到地点及可选设施并设置优先级，也可移除绑定。
- 用户修改的内置种子规则与绑定会转为 `seed_revision=0`，重新启动或重新导入地图不会覆盖；正在被行动队列使用的规则不能停用。
- 成人规则强制要求 player 目标、participants 可见以及 `sameLocation`/`targetOnline`，并且不能绑定成地点快捷按钮，因此仍只能走逐次邀请和明确接受流程。

## 数据和配置

默认数据库为 `data/wuxia.db`，首次运行自动创建、迁移并幂等写入完整世界和行动种子。已有玩家、编辑内容、活动路线和 `seed_revision=0` 的规则自定义会在安全升级中保留。可以通过环境变量调整：

```bash
DATABASE_PATH=/srv/wuxia/data/wuxia.db
PORT=3000
GAME_HOST=127.0.0.1
NPC_RUNNER_SECRET=replace-with-a-private-secret
NPC_TRADE_RUNNER_SECRET=replace-with-another-private-secret
PUBLIC_ORIGIN=https://wuxia.example.com
# 反向代理完成 OIDC 后，仅由可信代理注入以下身份头
OIDC_PROXY_SECRET=proxy-shared-secret
# 可选本地/受控部署编辑授权
EDITOR_PLAYER_IDS=player-id-1,player-id-2
# 可选：NPC_TRADE_STRATEGY_URL=https://internal.example/strategy
```

生产环境必须将 `DATABASE_PATH` 指向持久磁盘，并确保运行用户对目录有写权限。备份命令会使用 SQLite 在线备份 API，默认写入 `data/backups/`；也可以指定目标文件：

```bash
npm run db:backup -- /srv/backups/wuxia-$(date +%F).db
```

## 自托管

应用使用自定义 Node 服务在同一端口承载 Next.js 和 `/ws` WebSocket，不能部署到 Vercel 一类无常驻进程或无持久磁盘的环境。生产部署流程：

```bash
npm ci
npm run build
NODE_ENV=production DATABASE_PATH=/srv/wuxia/data/wuxia.db PORT=3000 GAME_HOST=127.0.0.1 \
  PUBLIC_ORIGIN=https://wuxia.example.com NPC_RUNNER_SECRET=replace-me NPC_TRADE_RUNNER_SECRET=replace-me-too npm start
```

建议使用 systemd、Docker 或其他进程管理器托管单个应用进程，并在前方放置 nginx。最小 nginx 配置如下：

```nginx
location /ws {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

进程收到 `SIGINT` 或 `SIGTERM` 时会停止 WebSocket、关闭 Next.js、执行 WAL checkpoint 并安全关闭数据库。

## 架构边界

当前实现面向一台持久化 Node 主机和一个应用进程。SQLite 以 WAL 模式运行，所有移动与行动使用短事务，实时层只发送增量事件，断线重连才发送完整快照。

未来扩展为多实例服务时，保留现有协议和游戏服务接口，将 SQLite 替换为 PostgreSQL 等共享数据库，并将进程内 WebSocket 广播替换为 Redis Pub/Sub 或专用实时服务即可。
